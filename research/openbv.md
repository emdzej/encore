# openbv: Babo Violent 2 on gasm

Source repo: `/Users/mjaskols/Projects/my/openbv` (read-only survey, 16 commits, 2026-10-09..10). Unlike
openrf/opensheep this is a **source port**, not reverse engineering: the GPL-3.0 C++ source was released
in 2012, so the game code is compiled as-is and only the platform beneath it is replaced. The novel part
is the **Go multiplayer server** written from a 2,300-line spec derived from the C++ server.

## 4. Technical knowledge that generalizes

### Main loop and timing
- Original: `WinMain` → `while (dkwMainLoop());`, `WM_PAINT` → `paint()` which updates at fixed 30 Hz
  (`dkcInit(30)`, `dkcGetElapsedf()` returns constant 1/30, catch-up loop) then renders.
- On gasm the runner owns the loop: `WinMain` is **cut in three** (`src/game/main.cpp` `#elif
  defined(OPENBV_GASM)`): `bv2_gasm_init` (everything before the loop) from `gasm_init`, one pass
  (`paint()`) per `gasm_frame` at 60 Hz (`gasm_set_frame_rate(60)`), shutdown from `gasm_exit`. Game logic
  stays 30 Hz internally via the engine timer reading the WASI clock — which gasm virtualizes in headless runs.
- **Audio sample budget per frame with remainder**: `n = (rate + rem) / 60; rem = (rate + rem) % 60` so
  22050 Hz / 60 = 367.5 samples averages exactly (`dkw_gasm.cpp`). Push stereo float via `gasm_audio_push`.
- Exit: on game quit call `bv2_gasm_exit()` then `__wasi_proc_exit(0)`.
- Threads: `CThread::start()` runs the work synchronously (`CThread.cpp`). Account HTTP requests via
  `curl_shim.cpp` fail like an unreachable host.

### Input (`src/port/dkw_gasm.cpp`)
- `gasm_input_mode(GASM_INPUT_KEYS_RAW | GASM_INPUT_POINTER_HIDDEN)` — the game draws its own cursor.
- gasm key codes → **DirectInput scan codes** table (physical keys, layout-independent), so the unchanged
  `dki.cpp` works. **Latched presses**: `keysDI | latchedDI` so a tap between two 30 Hz ticks still
  registers; latch cleared when dki reads. Same for mouse buttons (`latchedButtons |= pressed`).
- DirectInput mouse is relative: hand dki the delta `cursor - dkiGetMouse()` so its accumulated position
  tracks the absolute pointer exactly. Wheel: DI = 120/notch up-positive, gasm = +1/notch down → `-w*120`.
- Pointer mapped through `gl1_frame_rect` (letterboxed frame, bottom-left origin) into game pixels, clamped.
- Text: WM_CHAR delivered Enter as `\r`, Esc 27, Tab 9; gasm text input gives printable + `\b`,`\n` —
  synthesize Esc/Tab from key events, map `\n`→`\r`, decode UTF-8 and keep only Latin-1 0xA0-0xFF
  (game charset was Windows-1252).
- Gamepad: standard mapping → DI joystick convention (left stick X/Y, triggers combined on Z = btn6-btn7,
  right stick Rx/Ry); buttons unmapped.

### Rendering: OpenGL 1.x on GLES 3 (`src/port/gl1/`, 2.6k lines)
- Real GL 1.x entry points (`<GL/gl.h>` from `gl1/include`), so vendored code calls `glBegin` etc.
  unchanged. Don't link gasm's `gasm_gl.c` alongside (name clashes); call `gasm_gl_*` imports directly.
- **T&L on the CPU per the spec**: modelview, 8 lights (Blinn specular, local/infinite viewer, spot,
  attenuation, colour material, RESCALE_NORMAL/NORMALIZE), fog factor (linear/exp/exp2, |z| eye distance,
  per-vertex), projection, texture matrix. GPU gets clip-space verts + one shader (texenv
  MODULATE/REPLACE/DECAL/ADD, fog colour, alpha test, logic-op invert). Float math in wasm → identical on
  every runner (determinism).
- Batches break only on rasteriser-state changes (texture, blend, depth, cull, scissor, viewport, colour
  mask, polygon offset, alpha test, fog colour); matrix/light/material changes don't.
- Display lists record and replay commands, including nested `glCallList` and `glCallLists` with
  `glListBase` resolved at execution. Arrays go through the immediate path (dereferenced when compiled).
- **Offscreen RGBA8 + D24S8 framebuffer**: the game blends with `GL_DST_ALPHA` and copies the screen into
  textures; default framebuffer has no alpha. `gl1_end_frame` blits and forces opaque.
- Textures expanded to RGBA8 per base format, shader applies base-format rules (so `glCopyTexImage2D
  GL_RGB` works). Level 0 kept on CPU for `glGetTexImage` (font reads alpha back; blur reads RGB).
- `gluBuild2DMipmaps` as SGI GLU (nearest POT rounding at 1.5x, box filter, GLU rounding). Incomplete
  texture → texturing off (GL 1.x) not WebGL's black. `gluSphere` tessellation/texcoords exact (pole fans
  untextured, quad strips textured).
- Approximations: `GL_CLAMP`=`CLAMP_TO_EDGE`, no borders, no points/stipple/flat/two-sided/texgen/clip
  planes, `GL_EXTENSIONS` empty (so engine's extension checks find nothing — safe default).
- `tests/gl1/`: a gasm guest with 6 visual panels + PASS/FAIL checks (GLU round trips, attrib stacks,
  `glGetTexImage`, no gasm:gl errors under WebGL rules), same hash native vs Node null-GL.

### Audio: FMOD 3 shim (`src/port/fmod/`)
- Implements only what's used of `FSOUND_*`; `dks.cpp` unchanged. Platform contract: reader callback
  returning malloc'd buffer (shim never opens files), `fmodshim_mix_rate()`, `fmodshim_render(float*, n)`.
  Single-threaded, no clock: output depends only on call sequence → deterministic.
- 16 channels shared by samples and streams; handle = `index | serial<<12` (stale handles fail after
  reuse). Steal: lowest free, else oldest of lowest priority ≤ new (samples 128, streams 256: music never stolen).
- Mixing: linear interpolation, 32.32 fixed-point position; linear pan law; SFX master volume applies to streams.
- 3D: computed at mix time from listener as of last `FSOUND_Update`; gain `min/(min+rolloff*(d-min))`;
  pan from dot(dir, listener right), right = top x forward (FMOD 3 left-handed).
- Quirk reproduced: `FSOUND_2D` set by `dksPlaySound` is sticky, so a sample once played 2D stays 2D.
- Ogg Vorbis via stb_vorbis **streamed from memory** (Music.ogg 4.9 MB would be ~54 MB decoded). MP3
  unsupported (the one referenced file isn't in the data).
- Documented "uncertain" list (pan law, steal order at equal priority, 3D default for streams) — honest
  about what's from docs vs verified.
- `tests/audio/`: native C test of the shim against real sounds; per-check ok/FAIL, peak/RMS, hash, WAV out.

### Files, case, storage (`src/port/fs_gasm.c`, `win_find.cpp`)
- `fopen/remove/opendir/readdir/closedir/stat` wrapped at **link time** (`--wrap`), vendored code untouched.
- Path normalization: strip `./`, leading slashes, `\`→`/`, collapse `//`.
- Reads: gasm assets (read-only, case-insensitive lookup by runner — `main/Sounds/Hit.wav` vs
  `main/sounds/hit.wav`). Writes: gasm storage, key = lowercased path with `/` → `--`. **Stored file
  shadows the asset** (bv2.cfg, edited maps). Embedded assets (font) served before game data.
- `FindFirstFile/FindNextFile` emulated with Win32 wildcard matching and **NTFS order (sort by
  upper-cased name)** so map lists and rotation match Windows exactly.
- Case bug from Windows-origin source: includes `FastDelegate.h`/`screengrab.h` with wrong case broke
  Linux CI (`35dfb70`).
- Storage per id `openbv`: macOS `~/Library/Application Support/gasm/openbv/`; browser IndexedDB.

### SQLite without SQLite (`src/port/sqlite_shim.cpp`, 443 lines)
- bv2.db is 3 KB, 3 tables, 8 fixed statements. Shim parses the **SQLite file format's table b-trees**
  directly, answers those statements with `sqlite3_get_table`'s layout (column names then rows,
  row-major), saves changes to storage as `bv2db`. Constructed on first use because a global
  constructor (`GameVar`) reads bv2.db before the shim's globals init (static-init-order trap).
- MasterServers row replaced by launch param; bv2.db stores port+1000, game subtracts 1000.

### Two copies of the same classes (DLL boundary collapse)
- Engine DLLs and game each had their own `CString`, `CVector2i..4f`, `CMatrix3x3f` with **different
  semantics** (engine `EPSILON` 0.01 vs game 0.0001; `sscanf("%i")` vs `atoi`). Linking into one wasm would
  merge them (ODR). Fix: engine compiled with `-include engine_names.h` (renames: `CString`→`dkString`...),
  and functions crossing the old boundary (`dksvarRegister`, `dkglProject`, `dkpCreateParticleEx`...)
  get a fixed link name on both sides via `OPENBV_LINK(name)` on every declaration. Layouts identical.
- MSVC accepted temporaries bound to non-const refs; changed params to `const &` (no runtime change).
- Duplicate `rand(int,int)` in engine `CVector.cpp` `#ifndef OPENBV_GASM`'d out (identical to game's).

### Determinism
- Headless: virtual WASI clock, no threads, no wall-time. Same hash on native gasm-run, Node runner, and
  browser (hashframes mode). Golden: frame 600 `video_fnv32=1be66dd1 audio_fnv32=b56bc7ab audio_frames=220500`.
- Hash checked in CI, in each bundle via its launcher, and in the browser via headless Chrome.
- Network tests need `--realtime`; netlog is off by default so hashes stay unchanged.

### Networking

**Original**: baboNet DLL — TCP with own framing (9-byte key handshake, `"RND1"` + version + ids, then
`u16 size, u16 typeID, data`), optional UDP, plus a P2P UDP channel (LAN broadcast, server pings, remote
admin). `Server::host` calls `bb_serverCreate(false, MAX_PLAYER, sv_port)` → **UDP disabled**, so all
"UDP" messages actually travel on the reliable TCP stream. This made a WebSocket transport faithful.

**Transport on gasm** (`src/port/babonet_gasm.cpp`): gasm guests have only `gasm:net` WebSockets
(reliable, ordered, binary; browsers can't open raw sockets or listen).
- Client: `bb_clientConnect(host, port)` → `ws://host:port/`, or the host itself if it's a `ws://`/`wss://` URL.
- Frame = one binary WS message: `u16 typeID LE | u8 proto (0 TCP, 1 UDP — informational) | u8 0 | payload`.
- `bb_clientUpdate` codes kept: 3 connected, 1 failed, 2 closed by server.
- **Hosted games**: `bb_serverCreate` builds an **in-process loopback server**; the game's own client
  reaches it via `127.0.0.1`/`localhost`/empty/own IP + port. Others can't join (guests can't listen).
- baboNet semantics preserved because the game depends on them: `bb_serverUpdate` returns **one event per
  call** (new id > 0, lost id negated); connections admitted only at **0.5 s checks**; packets oldest
  first; `bb_serverReceive` drains the first client completely before the next; a received buffer stays
  valid until the next receive on that side.
- P2P UDP: sends dropped, nothing received. `bb_getMyMAC` → random MAC persisted in storage (servers ban by MAC).
- `--param netlog=1` prints every sent/received packet for diffing C++ listen server vs Go server.

**Protocol facts** (design/server.md):
- Client-trusting design: client integrates its own movement and sends coord frames; server interpolates
  remote players (cubic spline, `animTime = size/90`, extrapolate up to 15 frames) and uses that for hits;
  server owns projectiles, damage, spawns, flags, round state; **clients recompute scores themselves from
  `NET_SVCL_PLAYER_HIT` (remaining life ≤ 0 → kill)** — so the server must send exactly the same hits.
- Fixed 30 Hz, all float32. 21-step frame order with two `updateNet` calls (a connection accepted in the
  second gets NEWPLAYER after this frame's broadcasts). CTF/auto-balance live inside the
  `GAME_PLAYING` block — "the original's indentation makes it easy to miss" (corrected in `ffc4535`).
- Handshake: NEWPLAYER to all (client takes the first one as itself) → GAMEVERSION 21100 (client-side
  check) → PLAYER_INFO (name, account user, md5 pass, MAC) → GAMEVERSION_ACCEPTED(password) → state dump
  (SERVER_INFO, GAME_STATE, ~75 `set sv_x v` text cvars, ENUM_STATE per player, live projectiles, FLAG_ENUM).
  Pro checksum: HASH_SEED, 10 s reply timeout disconnects. Client drops most messages until SERVER_INFO → order matters.
- Map download: 250-byte chunks, rate `sv_maxUploadRate*1024/30` per frame, zero-size chunk = done,
  client resends GAMEVERSION_ACCEPTED. Original had path traversal and `fclose(NULL)` crash.
- Coord frames: position ×100, velocity ×10 as shorts (spawn position ×10). Send interval
  `max(avgPing, sv_minSendInterval + nbPlayers/8)`. Cvars to clients as console text with engine
  formatting (`%f` six decimals, bools true/false, quoted strings); cvar lookup is **prefix match**,
  first registration wins (`sv_maxPlayer` vs `sv_maxPlayerInGame`).
- Struct layouts: `sizeof` goes on the wire **including padding** (originally stack garbage; Go writes zeros).
- RNG: MSVC LCG `seed*214013+2531011`, `(seed>>16)&0x7fff`; helpers `rand(int a,b)` excludes upper
  bound; float `rand` uses `% (int)(eccart*30000/eccart)` and makes **no rand() call when from==to** —
  call counts must match for bit-exactness.

**Master server**: client sends `BV2_LIST(999){"2.11"}`, master replies `MASTER_INFO(1002){n}` (-1
outdated) then n × `BV2_ROW(997)` (134 bytes). Game servers send BV2_ROW every 20 s (first at ~5 s),
`KILL_SERV(1001)` on shutdown. Client pings each row via P2P UDP — no transport, so each times out after
1 s and shows `???`/1000; list fills one row per second. `ip` field is 16 bytes: `openbv.emdzej.pl` (16
chars) overflows → client patched so empty `ip` = master's host (`CMaster::gameHost`, `m_IP` 16→256 bytes,
`7172f85`). Original master `78.46.36.43:11207` dead. Original sent **passwords in clear** to browsing
clients and every player; Go sends `*` / `""`.

**Go server** (`server/`, `coder/websocket`, `go-oidc`):
- Packages: `wire` (framing), `transport` (WS, bounded send queue, pings), `bbnet` (baboNet event
  semantics), `proto` (every struct byte-exact vs Appendix A, golden tests), `bvmath` (float32, no FMA,
  musl `cosf`/`sinf` ported), `bvmap` (4 `.bvm` versions, rayTest, collisions), `cvar`, `game` (one file
  per C++ file ported, functions cite sources), `session` (30 Hz goroutine per session owns all state;
  admin talks via command channel processed at frame start — no locks in game code), `master`, `admin`
  (vanilla-JS static page, no build step), `store` (sessions.json, bans.json, audit.log), `reftest`.
- Sessions: own port each (`ws://host:<port>/`), or behind one HTTPS port at `/bv2/<id>` or
  `/bv2/port/<port>` (client accepts `wss://` URL as host; master-listed games joined at the master's
  `/bv2/port/<port>`, `83feffd`). Master on its own port 10207 or `/master`.
- Ops: env config (`OPENBV_LISTEN/CONTENT/DATA/ADMIN_TOKEN/MASTER_PORT/MASTER_REGISTER/CONN_PER_MINUTE
  (30)/TRUST_PROXY/MAX_SESSIONS (16)/ORIGINS/SESSION/DEBUG`), OIDC (public client, PKCE, role),
  `X-Forwarded-For` only with `TRUST_PROXY=1`, per-IP connection rate limit, Origin allowlist for the web
  player, distroless nonroot image with only `main/maps`, sessions restored at boot, audit log.
- In-game admin: `admin <user> <pass>` (MD5 hex compare as original), then `- <cmd>`; ~40 dedicated console
  commands; votes pass with >half of playing players in 30 s.
- Deviations documented per milestone in design/server.md §8.4 (bind playerID to sender, bounds checks,
  password never sent, map names confined to map folder, zero padding, per-session projectile IDs, etc.).

### Map format (.bvm)
Versions 10010/10011/20201/20202; u32 version, (20202) 25-byte author, (2020x) i16 theme/weather, i16
w,h, cells 2 bytes (bit7 passable, bits0-6 wall height; byte1 dirt splat), flag pods, objectives, spawn
lists (i16 count + vec3), 20202 has 4 tagged game-type blocks. `getInt` is 16-bit. Unknown block id
misreads the file (kept). 102 vanilla+Prozac maps covered by tests.

### Fonts
Engine font = 512x512 RGBA TGA, chars 33..159 in 64-px cells, glyph = run of columns with alpha,
separated by transparent columns. Baker adds an alpha=1 row along each glyph's advance so glyphs with
gaps (`"`, `%`) are read as one run whose width = advance. Placed to the original metrics (caps y 20 to
baseline 44).

## 5. Lessons learned / pitfalls

1. **Separate import commit**: vendor the original source normalized (UTF-8/LF) in its own commit
   (`eb9a62d`), so the port commit (`a7a4ffc`) diff is exactly the port. Mark every in-source change
   `OPENBV_GASM` with a comment; 12 markers in ~100k lines.
2. **Windows-origin case-sensitivity**: `#include` names with wrong case compile on Windows/macOS, fail
   on Linux CI (`35dfb70`). Also unanchored `.gitignore` `game/` matched `src/game/` so new files there
   were silently never added (`cfde746`) — anchor ignore patterns to root (`/game/`).
3. **One wasm module collapses DLL boundaries**: duplicate class names with different constants
   (EPSILON 0.01 vs 0.0001) silently merge under ODR. Rename one side via force-include + fixed link
   names (`engine_names.h`, `openbv_link.h`).
4. **Global constructor order**: `GameVar`'s global ctor reads bv2.db before the shim's globals exist →
   construct on first use (`sqlite_shim.cpp`).
5. **Float bit-exactness across languages/arches**: Go fuses multiply-add on arm64 → explicit float32
   rounding of each product; correctly-rounded `cosf` differs in last bit from musl's and `(short)(x*100)`
   amplifies it into a different coordinate → port musl's sinf/cosf to Go (`11ae1ce`). Build C++ reference
   drivers with `-ffp-contract=off`.
6. **NaN comparison in golden tests**: x86-64 and arm64 produce NaNs with different sign/payload; golden
   data from arm64 failed on x86-64 CI → compare NaN as NaN (`b790e1c`).
7. **C++ unspecified evaluation order**: `CVector3f(rand(), rand(), rand())` — clang evaluates x,y,z,
   MSVC x86 likely z,y,x. Chose clang order (matches wasm client, keeps it checkable) and documented
   (§8.4 milestone 3).
8. **Misleading indentation in the original**: CTF and auto-balance were inside the `GAME_PLAYING`
   block; spec initially got the frame order wrong, fixed in `ffc4535`. Verify control flow by compiling
   the original, not by reading.
9. **Fixed-size fields vs modern hostnames**: 16-byte `ip` can't hold `openbv.emdzej.pl` → empty-ip =
   master host, buffer 16→256 (`7172f85`).
10. **Virtual time vs network**: headless virtual time runs far ahead of real sockets; network tests need
    `--realtime` (AGENTS.md).
11. **Listen-server RNG is shared with client effects**, so recorded sessions can't replay draws exactly:
    `listen_test.go` instead searches the 30000 possible `rand(0,360)` values per bullet; 38/41 shots
    matched, 3 skipped (muzzle in wall depends on interpolated position) (`11ae1ce`).
12. **Presentation churn**: HUD redesigned (`9b2b316`) then mostly reverted next commit (`33742e1`) by
    user preference. Ask before restyling gameplay-adjacent UI; record decisions with dates in AGENTS.md.
13. **Doc drift**: after the server landed, `docs/index.md` ("Online play (in progress)... Not there
    yet"), `guide/browser.md`, `guide/hosting.md` and `internals/networking.md` ("In progress") still
    say no online play; menu screenshot caption says "as the original draws it" after the redesign. Add
    a docs-status sweep to milestone checklists.
14. **Sticky-state quirks in middleware**: FMOD `FSOUND_2D` stays set; reproduce, and list uncertain
    behaviours explicitly when only docs (not the DLL) are the source (`src/port/fmod/README.md`).
15. **Memory in the browser**: decode large Ogg as a stream from memory, not whole (4.9 MB → 54 MB).
16. **Security bugs in originals** are real for a public server: path traversal in map download,
    passwords echoed in clear, client-trusted playerIDs, unchecked array indices, stack overflow in
    `sendSVChange`. Keep valid-input behaviour identical, reject invalid input, document each deviation.
17. `gasm-run --compile` (AOT) only targets the host, so bundles ship plain `.wasm` (`package-gasm.sh`).

## 6. Reusable checklists / procedures

### A. Source-available port to gasm
1. Import upstream at a pinned commit, normalized to UTF-8/LF, only the files the target build uses, in
   one commit. Record the upstream commit hash everywhere (AGENTS.md, fetch-content.sh, docs).
2. Pick the reference configuration (here Windows ProRelease, `_PRO_`) and write it in AGENTS.md.
3. Replace the platform under the game in `src/port/` with API-compatible shims (keep vendored code
   calling the original APIs): window/loop/input (dkw), GL 1.x on GLES 3, sound middleware on a software
   mixer, sockets on WebSockets, files via `--wrap`, embedded DB via file-format reader, threads inline, HTTP failing cleanly.
4. Split `WinMain` into init / one-frame / exit; keep the game's own fixed-step timer, run gasm at 60 Hz.
5. Latch key/button presses between game ticks; convert absolute pointer to the original's relative deltas.
6. Check for duplicate-symbol/ODR hazards from merged DLLs; rename one side.
7. Fix include-case for Linux; anchor `.gitignore` paths.
8. Establish the headless golden hash (frame N, no input) and record it in AGENTS.md and a check script;
   verify native runner == Node runner == browser.
9. Write scripted-input recipes for reaching gameplay; generate site screenshots from them.
10. Content: if redistributable, fetch from pinned upstream with file count + tree SHA-256 check; never in git.

### B. Rewriting an original game server in another language
1. Write the spec first from source with `file:line` citations: authority split, exact frame order, every
   message, handshake order, timing in frames, RNG and every call site, quirks to keep, bugs to drop.
2. Generate struct layouts by compiling the original headers for a 32-bit target; zero padding on encode.
3. Reproduce the transport's event semantics (one event per poll, admission delays, drain order), not just bytes.
4. Implement the original RNG (MSVC LCG) per session with a fixable seed; match call counts exactly.
5. float32 everywhere, no FMA, port the client's libm trig; compare NaNs as NaNs.
6. Differential tests, three levels: (1) extract original functions verbatim (`extract.py`, `unifdef
   -DCONSOLE -D_PRO_`) into native drivers with stand-ins that record outputs → gzipped golden JSON
   committed, CI only reads; (2) packet logs from the client's in-process listen server replayed against
   the new server; (3) optionally the original dedicated build with patched rand/time.
7. Milestones by gameplay slice (handshake+movement → hitscan → projectiles → team modes → admin),
   each "done when" two unchanged clients agree on every screen.
8. Keep a deviation table per milestone with reasons.
9. Product layer: multiple sessions per process, each its own goroutine/loop and port, plus path-based
   endpoints behind one HTTPS port; master list; admin API/page with token+OIDC; audit log; bans; rate
   limits; trusted-proxy flag; Origin allowlist; healthz/readyz/version; distroless image; sessions persisted.

### C. Release / CI
- Build wasm with pinned released SDK; headless hash check; package per-OS bundles (runner + ANGLE +
  wasm + content + launcher + licences + README naming gasm version); smoke each on its own OS through
  the launcher with scratch HOME; shellcheck scripts; server cross-builds `CGO_ENABLED=0`; image built,
  run and exercised via API in CI; `.sha256` per artifact; plain semver tags.

### D. Browser player
- Vendor `@emdzej/gasm-host` from npm with VERSION; serve content with a `files.json` manifest keyed by
  content hash; Cache API for data, IndexedDB for saves; click-to-start for audio; raw-key
  `preventDefault`; tap/hold-Esc split; disable context menu; net allowlist with `ask: () => false`;
  `?hashframes=&input=` mode and a headless-Chrome test comparing to gasm-run.
