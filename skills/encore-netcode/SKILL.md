# ENCORE netcode

gasm gives a guest outbound WebSockets only — reliable, ordered, binary, no listening, no datagrams — and `gasm-relay` puts clients in rooms. Four routes were used across the ENCORE ports. Pick by what the original actually does.

## When to use

- The port reaches the original's DirectPlay, WinSock, IPX or custom network library.
- The original's servers (lobby, master, dedicated) are gone and need a replacement.
- Network play needs tests or a deployment.

## Inputs

- The original's network imports and initialisation (which providers, whether UDP is enabled, lobby host names).
- For source ports: the server source. For binaries: the network module's address range.
- A local `gasm-relay` (in gasm release archives, or `ghcr.io/emdzej/gasm-relay`).

## Procedure

### 1. Read what the original enables

Check the calls that create sockets or sessions. OpenBV's baboNet supports UDP but `bb_serverCreate(false, …)` disables it, so all "UDP" traffic was already on TCP — a WebSocket is faithful. List providers (UDP, IPX, TCP, modem), lobby/master hosts, and whether the simulation is driven by exchanged input words (lockstep candidate) or by state updates.

### 2. Choose the route

| Situation | Route | Example |
|---|---|---|
| Network play out of scope | Land on the original's own "no service provider" path (enumeration finds nothing, single-player rules apply) | OpenGTA |
| DirectPlay game | Emulate the DirectPlay subset over one relay room: enumeration, host/join with password, players, directed/broadcast messages, system messages, host migration to the lowest relay index | OpenCMR2 `src/net/dplay.c` |
| WinSock game with its own stack | Emulate WinSock; port the whole stack above it unchanged; relay index *i* = `10.0.0.(i+1)`, room `DATA` = broadcast, unicast = address-prefixed broadcast filtered by receivers | OpenNFSPU `src/real/wsock.c` |
| Custom library, server source available | Replace the transport (one WS binary message per packet); rewrite the server from a spec; verify against compiled original functions | OpenBV `src/port/babonet_gasm.cpp`, Go `server/` |

### 3. Emulate the transport's semantics, not only its bytes

Write down and reproduce, per call: events returned per poll (one per call in baboNet), admission timing (connections admitted only at 0.5 s checks), receive order (oldest first; drain the first client fully before the next), buffer lifetimes (valid until the next receive), disconnect reporting. Keep the original's netcode model above it (state per step, dead reckoning, both race modes).

### 4. Threads and timers

The guest is single-threaded and non-blocking. Either keep the network library's threads as gasm cooperative threads (`gasm_add_game(t LOOP THREADS …)`, Asyncify), or run thread bodies synchronously. Advance timers from the frame clock; a sleep inside a frame advances the timer so time-outs still fire. Poll `gasm_net_recv` every frame.

### 5. Dead servers

- If the original contains server-side code with no way to start it, start it behind a parameter (`--param netserver=1` in OpenNFSPU) and run it headless: `gasm-run game.wasm --asset-dir game --headless 100000000 --realtime --allow-net --param relay=ws://host:9123 --param room=r --param netserver=1`.
- Fixed-size fields vs modern host names: OpenBV's 16-byte `ip` cannot hold `openbv.emdzej.pl`; empty now means "the master's host", buffer grown to 256.

### 6. Rewriting a server (when the source exists)

1. **Spec first** (`design/server.md`), with `file:line` citations: authority split, exact per-frame order (verify by compiling, not by reading indentation), every message, handshake order, timing in frames, RNG and every call site, quirks to keep, bugs to drop, master protocol, milestones.
2. **Struct layouts by compiling the original headers** for a 32-bit target with the release defines; `sizeof` including padding goes on the wire; encode padding as zeros.
3. **Level 1 golden data**: extract original functions verbatim (`unifdef -DCONSOLE -D_PRO_`) into native drivers with MSVC `rand()` and the client's libm (`musl` `sinf`/`cosf`); write gzipped golden JSON; commit it; CI only reads it; the new code matches every case bit for bit.
4. **Level 2 packet logs**: add `--param netlog=1` to the client's in-process server; replay recorded client messages into the new server frame by frame and compare outgoing bytes. If the RNG is shared with client effects, search the draw's possible values instead of replaying it.
5. **Level 3** (optional): the original dedicated server built natively with `rand`/`time` patched, driven by the same scripted clients.
6. **Milestones by gameplay slice**, each done when two unchanged clients agree on every screen; a deviation table per milestone.
7. **Numbers**: float32 everywhere; round each product explicitly (Go fuses FMA on arm64); port the client's libm; compare NaN as NaN; MSVC LCG per session with a fixable seed and matching call counts; choose and document C++ argument evaluation order.

### 7. Server product layer

Sessions as one loop per session owning all state (commands via a channel at frame start, no locks in game code); each on its own port or behind one HTTPS port by path; health/readiness/version probes; config by environment; per-IP connection rate limit; `X-Forwarded-For` only behind a trusted-proxy flag; Origin allow-list for the web player; admin via token and OIDC; bans and audit log persisted; distroless non-root image; `CGO_ENABLED=0` cross builds; an image tag per main commit for infrastructure pinning.

## Hard rules

- Only message contents may affect the simulation, never arrival timing.
- Keep valid-input behaviour identical; reject invalid input. Fix security bugs of the original in public-facing code (path traversal, passwords echoed in clear, client-trusted ids, unchecked indices) and document each deviation.
- Packet logging off by default, so golden hashes do not move.
- Browser players on HTTPS can reach only `wss://` off the local machine.

## Testing

```sh
gasm-relay 127.0.0.1:9123 --max-peers 8 &  RELAY=$!
gasm-run game.wasm --asset-dir game --storage-dir /tmp/p1 --realtime --allow-net \
  --param relay=ws://127.0.0.1:9123 --param room=test --headless 3000 --input "<host script>" &
gasm-run game.wasm --asset-dir game --storage-dir /tmp/p2 --realtime --allow-net \
  --param relay=ws://127.0.0.1:9123 --param room=test --headless 3000 --input "<join script>"
kill $RELAY      # only your own relay's PID
```

- `--realtime` is required: virtual time outruns sockets and the instances never meet.
- Separate `--storage-dir` per instance gives each its own player.
- Native builds get an in-memory relay so protocol tests run in CI.
- Browser `?hashframes` cannot test net; use desktop runs.

## Pitfalls

- `gasm-relay` admits only 2 peers per room unless `--max-peers` is given.
- Hold scripted keys several frames; a one-frame tap may land in a frame without a simulation step.
- NaN payloads differ between x86-64 and arm64; golden data recorded on one fails on the other unless NaN compares as NaN.
- `(short)(x*100)` amplifies a last-bit libm difference into a different wire value.
- Pings over a P2P UDP channel have no transport on gasm; they time out (document it).

## Deployment

```sh
gasm-relay 0.0.0.0:9000 --max-peers 8
docker run -p 9000:9000 ghcr.io/emdzej/gasm-relay 0.0.0.0:9000 --max-peers 8
gasm-relay 0.0.0.0:9443 --max-peers 8 --tls-cert fullchain.pem --tls-key privkey.pem   # for browser players
```

Players: `--allow-net --param relay=ws://host:9000 --param room=<name>`; browser: `/play/?relay=wss://host:9443&room=<name>`. Desktop and browser share rooms.
