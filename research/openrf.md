## 3. Workflow & tooling

### Reverse engineering
- **Ghidra** project `returnfire`, program `rfire_game.exe` (a copy of `cd/RFIRE.BIN`), driven headlessly through
  **ghidra-cli** (https://github.com/akiselev/ghidra-cli): `ghidra decompile 0xADDR --project returnfire --program rfire_game.exe`,
  plus `x-ref`, `disasm`, `memory`, `strings`, `rename`. (A Ghidra MCP is also available in this environment, but the repo documents the CLI.)
- **Full decompile dumps for grepping**: `tools/ghidra/DumpAllNamed.java` writes `re/all_named.c` (41.6k lines, current names);
  `re/all.c` = original unnamed dump (825 fns), plus `decomp.json`. `re/` is git-ignored. Rename in Ghidra as you learn and
  regenerate the dump so code, docs and Ghidra share names.
- Pitfall noted: `FixMul` (0x438300) is `__fastcall` (ECX, EDX); Ghidra hides its arguments until the signature is set.
- Multi-agent RE phase is visible in the docs: `architecture.md` refers to "the ART.CAR agent", "the RFM agent", "the video agent",
  "the game-logic fork". Each format had an owner who wrote `docs/<fmt>.md` + `tools/<fmt>.py` + samples in `out/<fmt>/`.
  `docs/CONTEXT.md` is the original agent briefing (known formats, TBD list, output conventions), excluded from the site.
- `architecture.md` §4 is an explicit **recommended reimplementation order** (platform shell -> asset loaders -> cel rasteriser ->
  world view -> object system -> vehicles -> weapons -> enemies -> HUD -> sound/music -> front end -> 2P/replay), written before porting.
- Every RE doc ends with an **"Open questions"** section (unverified fields, untraced paths), which keeps confidence explicit.

### Agent instructions (AGENTS.md patterns that look effective)
- **"Fidelity is the product"**: reproduce quirks and bugs (lobbed tank shell that never lands, unused per-event sound frequencies,
  drone pitch limit that never applies). "If it looks wrong, check the disassembly; if the original does it, keep it and add a comment."
- **Hard legal rules**: never commit `cd/`, `rfire_game.exe`, `re/`, `out/`; no data copied from the exe into source (tables loaded
  at runtime); cite original addresses; never paste decompiler output, write in own words.
- **"Before claiming a change works"** checklist: all tests exit 0, `render_cmp.py` 0 mismatches, refactors byte-identical test output
  (`out/sfx/test.wav` too) and identical gasm hashes, look at a headless frame for anything visible.
- **Golden hashes in AGENTS.md**: `--headless 689 ... demo=fire` -> `video_fnv32=d014dcfb audio_fnv32=f1520dc1 audio_frames=486158`;
  2P `--headless 900 demo=2p` -> `660f4ab4 / 31f91835 / 635040`. Must match on gasm-run (folder and image mode) and the Node runner.
- **"Traps (already solved: don't reintroduce)"** section: one paragraph per hard-won fact (see §5). Very effective memory for agents.
- Safety for unattended runs: never open a gasm-run window, **never use macOS `screencapture`** (captures the user's desktop), point
  `HOME`/`XDG_*` at scratch dirs for launcher tests, `OPENRF_CD` turns a missing CD into exit 2 instead of a dialog, `--dry-run`.
- Architecture invariants stated as rules: no blocking loops, never call `plat_poll` yourself, keep the number/order of presents and
  `plat_ticks_ms` reads, all file access through `vfs.h`, only `platform_gasm.c` includes `gasm.h`.
- Style rules: no emojis on site, describe as cross-platform via gasm, hotlink the official badge without recolouring, imperative commit
  subjects, tags without `v`.
- `design/gasm-host-requirements.md`: a **requirements doc written by the game repo for the runtime repo's agent** (R1 file-backed
  assets, R2 `--asset-dir` with case-insensitive lookup, R3 Worker mode + OPFS provider, R4 second keyboard layout, R5 enumeration
  deferred), with acceptance criteria and "numbers come from real runs". Implemented in gasm 0.3.0 (`39830c7`). Good pattern for
  cross-repo agent work.

## 4. Technical knowledge that generalizes

### Data access / FS
- Single VFS (`src/vfs.h`): `vfs_read_all`, `vfs_open` + **positional stateless** `vfs_read_at`, `vfs_size`, `vfs_exists`, `vfs_list`.
  Names disc-relative and **case-insensitive** (disc is upper case, game code mixed case, `strncasecmp` in ISO lookup).
- Backends: host directory (component-by-component case-insensitive lookup) or **ISO 9660 image over a `VfsSource`** ("read bytes at
  offset" callback). ISO tree read once at mount. Sector format auto-detected from sync pattern + PVD: 2048 plain, 2352 MODE1 (16-byte
  header), 2352 MODE2 form 1 (24-byte header). Same reader works over a file (`pread`) or `gasm_asset_read_at`.
- gasm `--asset-dir` mode: names tried as spelled and upper-cased; `vfs_list` probes `RFMAPnnn.RFM` names since there is no enumeration.
- Manual bin->iso: copy `s[16:16+2048]` of each 2352-byte sector (`docs/howto/extract-cd.md`).
- Original exe as a data source: `src/exe.c` checks size + CRC-32, maps PE sections to RVAs in a `SizeOfImage` buffer, runs registered
  `EXE_LOADER(fn)` loaders; code reads by VA via `exe_ptr/exe_u32/exe_s32/exe_str`. Some descriptors (explosion scripts) are interpreted
  in place from the mapped image (`rf_u32`/`rf_ptr`). Python side: `tools/rfexe.py` (lookup `$OPENRF_EXE`, `cd/RFIRE.BIN`, `rfire_game.exe`).

### File formats decoded
- **ART.CAR** (`docs/car.md`): magic `CCBA`, relocatable memory image of 2165 **3DO CCBs** (0x44 bytes: 3DO 60 + width/height),
  pointers are file offsets rebased by load address; pixels converted to uncompressed 8-bit row-major; `PRE0` reused as PC draw mode
  (0 copy, 1/2 shadow darken, 3/4 50% blend, 5 additive light, 0xD span-list shadow mask, 0x10 key-blend, 0x11 PLUT remap, 0x12 remap+blend).
  HDX/HDY are 12.20, VDX/VDY 16.16. Shift table (log2 dims). Two palettes: BGRx game palette and Win32 `LOGPALETTE` with game colours at
  **+10** (slots 0-9, 246-255 are Windows system colours). Runtime patches in `Car_Load` (key-blend ranges, scratch surfaces for 1981-1986).
  Sprites addressed by index only (no names).
- **TRANS.TBL** (81,924 bytes): a cache the game generates itself: `blend[a][b]` 64 KB, `darken[32][256]`, `brighten[32][256]` via nearest
  colour by RGB squared distance. Regenerable bit-exact from the LOGPALETTE.
- **RFA / TITLE BMP**: plain 8-bit Windows BMP, bottom-up. `.SDT` = plain RIFF WAV.
- **RFM maps** (`docs/rfm.md`): `WRL\0`, 128x128 one byte per tile (32x32 px tiles, world 4096 px, cell = 0x200000 in 16.16), tagged chunks
  `NAME`, `VHCL` (vehicle stock overrides, 0xFF = default, random mine count), `LEVL`, `EDTN` (0x03270327 = stock). 204 maps (100 1P,
  104 2P). Tile byte -> 240-entry table `{terrain, object, team, handler}` in the exe; handlers for home pad / flag site; one real flag
  chosen randomly among sites (rest decoys); bridge fill between abutments; NAME chunk contains leftover editor memory (ignore).
- **STM movies** (`docs/stm.md`): AVIFile dump header (0x9A0 bytes: two `AVISTREAMINFOA`, `PCMWAVEFORMAT`, `BITMAPINFOHEADER`s) then
  fixed 64 KB super-blocks (TWI: 0xE800) with video records (next offset, keyframe flag, frame number, raw Cinepak frame) and audio at the
  block end. Cinepak 320x240 15 fps (RF.STM greyscale codebooks 0x24xx-0x27xx), PCM 22050 Hz stereo 16-bit. First 1-2 blocks audio-only
  (1.5 s preroll). Video slaved to audio clock; skip to next keyframe when > 4 frames behind. OpenRF has its **own Cinepak decoder**
  (`src/cinepak.c`, from the public bitstream description) decoding to true colour (original dithered to an 8-bit palette).
- **SCORE.WAV**: one 223 MB 44.1 kHz stereo file (~21 min) holding all music; an 18-entry track table in the exe gives byte ranges
  **relative to the data chunk** (start/alt-loop-start/end) and transition lists. `DRUMS.WAV` has a `fact` chunk: always locate `data`.
- **High scores** `RFire_HS`: original binary format kept (`{0x1c,"rfhs",n1P,0x48,n2P,0x50}` header, 1P records level/map/player/ms,
  2P records name pair sorted + wins/draws).

### Rendering on gasm
- Logical 320x240; hi-res 640x480 = same cels rasterised at 2x (corners `>>15` instead of `>>16`, clip doubled). Full-screen pictures
  have separate hi/lo bitmaps. Backend converts the 640x480 8-bit framebuffer through the palette to RGBA for `video_present`; movie
  frames presented at 320x240 RGB and the runner scales both to the same 4:3 output (mixed-size presents are fine on gasm).
- Software port of the 3DO cel engine: display list of CCB copies (256 pool, auto-flush), quad edge-walk rasteriser + span functions
  per mode, painter's order (floor rows far->near interleaved with depth-sorted queued 3D models). Projection table `T[i] = 300/(300-i)`,
  64-step yaw/pitch matrix tables, row vectors, each term `FixMul`ed separately.
- Palette fade is **subtractive** (`c - ((0x10000-b)>>8)`), not multiplicative; fullscreen sets 256 entries, entries 0..10 forced black.
- Viewports: 1P 320x152; 2P two 156x149 at x=0 and x=164; status bar BMP under HUD cels; 128x128 radar image.

### Audio
- One mixer `audio_render(float*, frames)` 44100 Hz stereo summing: music stream (`vfs_read_at` ranges, loop, seamless continue, volume
  fades 0x444 per 16 ms tick), movie PCM (22050 -> 44100 linear resample, pushed whole at open), and `sfx_render` (port of the original
  priority mixer: 20 voices, 15 logical instances, priority with decay, per-side budget 0x7fff so loud sounds starve others, volume
  `min(0, max(L,R)/3 - 2200)` dB-ish, distance gain `clamp((0x1a8-dist)/0x180,0,1)`).
- Two-listener stereo: gain L from player 1 listener, gain R from player 2; in 1P both are P1's camera at x-10/x+10 (slight spread).
- On gasm the mixer is pulled **on the frame**: `audio_frames_for_frame(125, 2)` with carried fraction (705 or 706 frames at 62.5 Hz;
  735 at 60). Movies slaved to frames rendered so far => movie playback reproducible in headless hashes.
- Original DirectSound oddities kept: sample-rate field never written so event frequency ratios evaluate to 0; loop markers never read.

### Timing / determinism
- Original tick: `timeGetTime()>>4` = 16 ms (62.5 Hz). Variable timestep: delta = elapsed whole ticks clamped 0..12 (`-f12`), motion =
  rate * delta in 16.16. No frame limiter except Flip vsync.
- gasm: `set_frame_rate(62.5)`, one `app_frame` per `gasm_frame`, `plat_ticks_ms` = 16 ms per present (virtual, never wall clock).
  Frame N shows game time 16*(N-1) ms; time T -> `N = ceil(T/16) + 1` (11000 ms = frame 689). Because the original's delta is then always
  1 tick, frames are byte-identical across runners.
- Determinism kit: integer maths, **MSVC `rand()` port** (`holdrand*214013+2531011`, `>>16 & 0x7fff`) + `RandRange` exactly as original
  (`(2r*n)>>16`), no wall-clock reads in the sim. Map tile-byte sum feeds an RNG seed (FUN_0041f190).
- Frame-driven app loop: every former blocking loop (intro, title, game, end sequence, viewer) is a state with a step returning
  `STEP_FRAME | STEP_AGAIN | STEP_DONE`; `app_frame` polls, steps, repeats until a step presents. One step = one iteration of the old
  loop, so presents and clock reads are unchanged => byte-identical vs the blocking version (`1247f21`). Movies and fades are reusable
  stepped objects.

### Input
- One 32-bit input word per player per frame (cur + prev for edges). Bits 0x40000000 up, 0x80000000 down, 0x10000000 left,
  0x20000000 right, buttons 0x08/0x04/0x02 000000, 0x00200000/0x00400000 buttons 4/5. Digital directions must also set **magnitude
  bytes** (`0xff` low byte for L/R, `0xff00` for U/D) or vehicles move at 1/256 speed.
- Key codes in `keys.h` = USB HID usages (= SDL scancodes = gasm raw keys). gasm 0.5+ `input_mode(KEYS_RAW)` disables gasm's keymap so
  original bindings (P1 WASD+HJK+QE, P2 numpad, Alt+3 swap sides, F2/F3, 1-9) apply; `key_events` for "any key" edge; latched at first
  poll of a frame. Pads via `input_pad(0..3)` with gasm 12-button layout. Original AZERTY defaults for French, NumLock remap exist.
- 2P original quirk: `GameFrame2P` polls input after objects update => vehicles see previous frame's input (one-frame lag), bunker
  screens fresh input. Ported as is.

### Storage, params, errors
- `plat_storage_get/set("RFire_HS")` -> `gasm:storage` (browser: IndexedDB namespace `openrf`); tests use a file
  (`~/Library/Application Support/Return Fire/`, `OPENRF_HS` override).
- Launch params (`--param k=v` / URL query) replace argv/env; backend puts them into wasi-libc `setenv` so the core's `getenv` works
  unchanged. Errors: `log` + `gasm_init` returning 1; quit = `app_exit` + `proc_exit(0)`.

### Networking
- None yet. Roadmap: online 2P via deterministic lockstep (exchange input words, periodic state hashes) over swsrs relay or gasm
  `gasm:net`/`gasm-relay`. The 2P sim already runs both players from input words, so determinism is the enabler.

## 5. Lessons learned / pitfalls (evidence)

1. **Rendering mutates game state** (AGENTS.md Traps): turrets activate from the draw pass (`Model_TowerHook` 0x4174e0), soldiers removed
   after 120 undrawn ticks, wreck timers count from last drawn tick, idle-drone gate reads "enemy turrets in view last frame". Headless
   tests must render the view; you cannot run the sim alone.
2. **Palette +10 offset**: sprite pixels index the DirectDraw LOGPALETTE (game palette shifted by 10). Verified only visually (water/sand
   right only with LOGPALETTE) and confirmed by `GetNearestPaletteIndex(...) + 10` in mode 10 (`docs/car.md`). RFA status bars need +10.
3. **Input magnitude bytes** or 1/256 speed (Traps).
4. **Don't lay out in 640x480**: logic is 320x240; hi-res is a rasteriser 2x (Traps; `architecture.md` §1).
5. **Calling convention hides arguments**: `FixMul` `__fastcall` (AGENTS.md RE section).
6. **x87 vs libm**: `FixDiv` uses 80-bit x87 + `_ftol`; `fsin/fcos/fpatan` may differ in last ulp => rare off-by-one in generated tables
   (`docs/render.md` §8, `docs/game.md` §8). Build tables with integer-exact formulas where possible.
7. **Original races exist**: second lift launched while the previous lowering lift exists is deleted by the old lift's `hit_object`
   (equal priority) leaving no vehicle; tests wait around it rather than fixing (`docs/game.md` §8).
8. **Wall-clock screenshots aren't reproducible**: before `9492abc` docs screenshots came from the SDL build's wall-clock frames; moving
   to gasm-run headless made them byte-reproducible (`cmp` PNGs before/after refactors).
9. **Host API drift across runtime versions**: gasm-host 0.6.0 changed `GasmWorker.frames` to `FrameStep`s; the raw keyboard silently
   stopped reaching the game until the call changed (`9492abc`). gasm-host 0.4.0 made `gasm-worker.js` import `webgpu-gfx.js`; without
   vendoring it the play page never started (`4f57aec`). Rule: read the runtime CHANGELOG on each pin bump and re-run the browser test.
10. **python -m http.server backlog 5** resets parallel module loads of gasm-host 0.6.0 `lib/*.js` (`9492abc`); test server uses 128.
11. **Paths with spaces/parentheses** (`Return Fire (Europe) (En,Fr,De,Es,It).bin`): CMake custom commands need `VERBATIM`, launchers need
    quoting (Traps).
12. **Shell portability**: `A && B || C` flagged by CI's older shellcheck (SC2015), rewritten as if-statements (`d7c4cd6`).
13. **macOS universal binary dependency check**: `otool` per-architecture header lines misread as non-system libraries (`8030308`).
14. **Memory/latency with big assets**: whole-image asset cost ~300 MB RAM + slow start in early gasm; Node runner preloads `--asset`
    files (~750 MB RSS with the `.bin`) but reads `--asset-dir` on demand (~70 MB) (AGENTS.md). Drove gasm R1-R3.
15. **macOS TCC**: "Operation not permitted" for CDs in Downloads/Documents/removable volumes; documented fix (`docs/guide/troubleshooting.md`).
16. **Audio thread safety**: an old SDL backend pulled the mixer from another thread; keep `audio_lock()` around mixer state changes and
    keep reads positional (no shared `FILE*`) so threaded hosts can return (Traps).
17. **Edge-triggered input and state changes**: `plat_poll` before every state step consumes edges at each state change, matching the
    old nested loops; backends must tolerate multiple polls per frame (Traps).
18. **Decoder confidence**: STM decoded with cross-checks (audio byte totals = header, contiguous frame numbers, padding 0..3) for all 7
    files before trusting it (`docs/stm.md`). Garbage in AVI name fields ("PAL ") looked like chunks but wasn't.
19. **Unused original fields**: many header bytes are editor metadata or never read (RFM 0x04, 0x41; STM 0xB4); document "never read" with
    the reader address rather than guessing semantics.
20. **Legal hygiene shaped architecture**: no tables in source => runtime PE mapping + generated descriptors; supports exactly one CRC so
    every address is valid (other builds -> "please report size + CRC").

## 6. Reusable checklists / procedures

### A. Starting a disassembly-driven reimplementation
1. Identify the real binary (launchers/language stubs vs game). Record size + CRC-32; refuse others at runtime with a helpful message.
2. Import into Ghidra; script a full named decompile dump (`DumpAllNamed.java`) into a git-ignored `re/`. Fix calling conventions of hot
   math helpers first.
3. Write `docs/architecture.md`: key facts table, module map by address range, program flow, per-frame order, timing, input word, globals,
   function index, **recommended port order**, open questions.
4. Per file format: `docs/<fmt>.md` (byte layouts + reader addresses + open questions) and `tools/<fmt>.py` decoder writing samples to
   git-ignored `out/<fmt>/`. Cross-check totals/counts across all files.
5. For the renderer, write a bit-exact **Python reference** from the disassembly first, then port to C and diff index buffers
   (fixed scenes + seeded fuzz scenes). Require 0 mismatches.
6. Port function by function, citing `/* Name 0xADDR */`; keep fixed-point and RNG exactly (MSVC LCG). Keep bugs; comment them.
7. Load exe tables at runtime (PE map + VA readers) with generated descriptor modules; never commit data.

### B. Portable core for a frame-driven runtime (gasm)
1. Platform contract header: video (indexed fb + RGB present), input (keys as USB HID, pads), virtual ticks, audio lock, storage, error.
2. Convert every blocking loop into states with step functions (`STEP_FRAME/AGAIN/DONE`); keep present/clock-read order.
3. Virtual clock = original tick per frame; choose frame rate = original tick rate (62.5 Hz for 16 ms ticks).
4. Single mixer pulled per frame with carried fractional frame count; slave video to audio frames.
5. VFS with case-insensitive names, positional reads, ISO 9660 (2048/2352 MODE1/MODE2) over a read-at callback; also folder-as-assets mode.
6. Launch params -> `setenv` so `getenv` in the core keeps working; scripted `demo=` input modes for every subsystem.

### C. Verification gate before any commit
- All headless tests exit 0 against real data, with folder and disc image.
- Renderer diff = 0 mismatches.
- Golden `video_fnv32/audio_fnv32/audio_frames` hashes on native runner (folder + image) and Node runner match the recorded values.
- `tools/screenshots.sh` before/after, `cmp` PNGs.
- Browser: `web-play-test.mjs` PASS all cases; inspect saved PNGs.
- For refactors, byte-identical test output (including WAV dumps).

### D. Runtime (gasm) pin bump
1. Change SDK pin (`fetch-gasm-sdk.sh GASM_VERSION`) and npm `@emdzej/gasm-host` together.
2. Re-run vendor script; read the runtime CHANGELOG for host API changes.
3. Verify hashes, browser test, bundle smoke tests on each OS.

### E. Browser player
- Folder picker with webkitdirectory fallback, validate required files + exe size, import only needed dirs to OPFS, write completion marker
  last, offer play-without-import (Blob provider), run in Worker mode (no COOP/COEP), compile module once, expose `hashframes` and a
  frame-PNG hook for automated tests, never put game data in `public/`.

### F. Release
- Bump CMake project version, tag plain semver, CI builds wasm + 4 bundles, smoke-tests each on its OS, attaches with `.sha256` and
  release notes covering first-run OS warnings (Gatekeeper `xattr -dr com.apple.quarantine`, SmartScreen "Run anyway", Linux ALSA).
